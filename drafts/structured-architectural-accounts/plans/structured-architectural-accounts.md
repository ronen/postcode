# Structured architectural accounts

Status: in review
Created: 2026-11-15
Updated: 2026-11-15

## Problem and intended outcome

PostCode retains qualified interpretations and mechanical findings, but their organizing mechanisms differ. Whole-investigram corrections, fixed composition trees and broad generating-evaluation exposure are too coarse for reusing one identifying description, revising a particular use of content, or retaining several competing answers. Structured architectural explanations also need explicit meaning that a diagram can render without inventing claims.

Establish one mechanism for retaining and organizing qualified analysis contributions from all existing producers. Immutable investigrams carry analysis content and qualified organizing declarations. Entities identify things in the system under study; separate Query results organize answers to particular investigation invocations. Exact association declarations add, supersede or withdraw uses of content. Exposure records actual producer inputs, and derived reconsideration retains identifiable causes. This supports overlapping, partial and contradictory accounts without constructing one reconciled architectural model.

Subject, Lens, Projection, Presentation and View remain the application concepts. A Lens selects its qualified answer from engine information; the immutable Projection captures that selection. An investigram is neither a Projection nor necessarily the whole answer. Retrieval and answer assembly create no production exposure.

The deliverable is the mechanism, migration of all existing mechanical information and agentic capabilities, and a small real application of it: state-dependent behavior with a supported state diagram and retained follow-up-option execution. It is not the selection of PostCode's initial user-facing investigation catalogue. A recognizable architectural inquiry is a sanity check on the mechanism, not a separate proof of user value or interpretive superiority.

## Representative use and ownership

A module discovery producer identifies a circuit breaker. An agentic investigation identifies Half-open and explains admission behavior. A later inquiry reuses the same Entity, supplies fuller identifying information, and revises an admission association while retaining the original content. It can also redesignate the earlier Query result when it changes that answer. An independent account can disagree without either being selected as globally correct. A state diagram uses retained states, guarded transitions and effects, with qualification accessible alongside it.

The exact example and codebase are implementation choices. The behavioral claims are not predetermined acceptance answers. Controlled responses exercise rare declaration and failure cases; live trials establish that the actual integration can produce and consume useful-shaped qualified content.

| Information | Owner and effect |
| --- | --- |
| Content item, evidence, qualifications | Immutable owning investigram; references do not transfer ownership or strengthen claims. |
| Entity identity | Session identity; names and descriptions are qualified associated information. |
| Association declaration | Producing investigram; exact new use or displacement of earlier uses. |
| Query result and designation | Invocation-specific organizing target and immutable selection; a new designation does not mutate the old selection. |
| Follow-up option, illustration, inconsistency report | Qualified investigram metadata with exact references. |
| Exposure | Actual input supplied to the producing execution, attributable to each produced investigram. |
| Standing and reconsideration | Derived from retained declarations, deliveries and membership, with exact causes. |
| Projection | Lens-selected content, basis, qualification and status snapshot; exact presentation follows fixed support. |

## Scope

- Introduce a common internal producer/contribution boundary, atomic validation and retention, stable Entity and Query-result identities, content items, declarations, qualified metadata and exact access.
- Migrate module and symbol identification, exports, dependencies, associated documentation, module composition, repository/project organization, groups, containment, placement and their qualified properties. Preserve existing provider algorithms and guarantees unless an explicitly approved change is needed.
- Migrate `summarize`, `explain`, `decompose`, `examine`, prose output, prior-result follow-up, inspection and status access. Remove the legacy whole-investigram correction, composition-tree and citation-exposure regime at completion.
- Provide association and inventory/selection-scope acquisition, baseline subject identification, explicit-referent discovery, qualified historical name lookup, exact result access and cause-bearing reconsideration.
- Implement one architectural concept, state-dependent behavior; supported content-type contracts; one real bounded state-diagram type and renderer; optional authored illustrations; and explicit diagram requirements using the existing result/Presentation contracts.
- Expose the representative investigation and execution of a retained follow-up option through supported application APIs. Register explicit subject signatures and result contracts. New public command names, GUI controls or menus are not required.
- Rename the supplied-content citation index to exposure index throughout affected governing documents, APIs and code. Evidence citations and supporting evidence retain their distinct meaning.
- Update affected references and descriptive architecture to match the implemented result, including migration of existing CLI behavior and exact-answer access.

## Non-goals

No persistence, cross-session identity, changed-program correspondence, general semantic merging, automatic identity supersession, reconciled architecture, universal ontology, new mechanical analysis algorithms, broad graphical investigation, investigram nesting or automatic organization. Architectural Entity organization beyond existing mechanical organization is also deferred.

No reassessment or clearance, investigator-directed propagation or suppression, declared semantic dependencies, automatic investigation scheduling, user objections to investigators, declaration reinstatement, or automatic policy preventing deliberate reassertion. Equivalent recomputation does not itself reassert a displaced association. No new notification subsystem, global investigation catalogue, relevance-based operation ranking or soft signatures is required.

Interaction/composition diagrams remain later probes. The state diagram is a mechanism validation capability, not a full UML implementation, simulation engine or presentation system. Existing source-access, hosted enablement, credentials, observations, resource ownership and Session restrictions remain in force.

## Observable success criteria

1. All in-scope producers retain qualified information through the common contribution model, with one consistent Entity identity/lookup contract and no permanent parallel legacy regime. Mechanical guarantees remain attributable to their actual methods.
2. Cross-producer addition, supersession, withdrawal and content reuse preserve exact ownership, provenance and qualification. Invalid submissions leave no partial accepted contribution. Valid partial fulfillment processes all accepted declarations normally.
3. Exact old content, association uses, Query-result designations and Projections remain available within the supported Session. Later declarations change derived standing and fresh selections, never those captures. All equally standing designated alternatives remain distinct.
4. Exact-content exposure and acquired inventory/selection scopes have the agreed different effects. Cause identities survive direct and transitive propagation; no exposure is fabricated by answer assembly, human browsing, host identity matching or result membership.
5. Equivalent native recomputation reuses established information without silently renewing withdrawn uses. Native identity scope and common IDs remain separate. Real answer assembly and actual retained-input production are verified separately.
6. Baseline context supplies all standing identification associations for each subject Entity with qualification and coverage. Additional acquisition and referent-based discovery work without an invented navigation origin. Historical names can locate their Entity with honest standing and ambiguity.
7. A few focused live trials collectively produce qualified structured state behavior, retain/retrieve it, render the requested real state diagram, and execute a retained follow-up option acquiring prior information through the supported application boundary.
8. Controlled coverage proves outcome, contract and lifecycle behavior independently of agent spontaneity. An unmet diagram requirement is disclosed even when other accepted information is useful. Diagram compatibility is checked for every alternative covered by the request.
9. Existing migrated capability, identity, exact-presentation, application/worker, qualification and CLI checks pass at final integration. Documentation distinguishes supported API capabilities from absent UI routes and makes no claim of persistence or general architectural completeness.

## Milestones and review checkpoints

### 1. Common contribution mechanism

Define the producer/contribution boundary and implement identities, typed content, immutable declarations, Query-result designations, exact retrieval, exposure, standing and cause propagation. Use controlled producers, including independently attributed cross-producer contributions. Compiler operations and agent dialogs need not share an execution protocol.

Verify identity resolution before allocation; reference/role/type integrity; atomicity; reused content and submission-wide reachability; alternatives; qualified inconsistency; known versus later change; inventory additions; result membership; and outcome separation. Demonstrate that one acceptance batch does not union independent producers' exposure. Record the concrete schema and contract tests for review without treating exploratory payload spelling as binding.

Checkpoint: review mechanism semantics before expanding native integration. Record affected legacy check families and intended restoration milestones. This milestone alone does not demonstrate the real application path.

### 2. Early vertical application

Integrate real module identification and the portion of exports needed to assemble an export answer using retained module naming. Separately exercise a real producer consuming retained mechanical information and recording that exposure. Integrate agentic state-dependent behavior, a real state-diagram contract/renderer, accepted partial outcomes, declarations and a retained follow-up option executed through the application API.

Run focused live trials and controlled dialogs across acquisition, retention, exact access and rendering. A read-only assembly of export information must not create production exposure; a producer that consumes retained module information must record it. Exercise equivalent provider recomputation after displacement without new associations. Verify naming qualification and mechanical semantic content survive the wrapper.

Checkpoint: human-arranged independent review of the vertical result, instruction usability, identity/exposure attribution, warning breadth and known dependency gaps before completing the remaining migration. A failed live attempt can inform repair but cannot replace the successful-path demonstration.

### 3. Complete producer and caller migration

Complete remaining module/symbol/export variants and callers; migrate dependencies, associated documentation and composition; then organization groups, containment, placement and properties. Migrate all existing agentic operations and their consumers. Remove fixed investigram trees and whole-investigram correction selection, preserving meaningful content references, exact subjects and qualified decomposition. Complete exposure terminology changes.

Verify all existing answer families through their declared question/method contracts, including inspection's mixed mechanical and associated-content selection. Preserve zero/one/many lookup, incomplete populations, opaque/unresolved dependency distinctions, stable aliases, deterministic mechanical content, and qualified organization schemes. Verify original and redesigned answers, conflicting alternatives, historical-name discovery, exact presentation and retained follow-up.

Checkpoint: review migration coverage and remaining gaps, including whether any native producer has silently bypassed the common semantics. This plan includes all these families; review does not automatically move unfinished migration into another plan.

### 4. Integrated verification and documentation

Exercise the completed families together within one supported Session, across direct API and existing CLI/worker paths. Repeat affected live checks only when migration or findings justify it. Run repository-required type, build and test checks and the final integrated review workflow. Restore all intentionally unconformed check families; intermediate expected failures are not permanent waivers.

Update capability/CLI references, descriptive architecture, method versions and implementation conventions as warranted by the delivered behavior. Describe actual representative API routes without claiming new CLI access. Preserve current observation, human-output, credential and cancellation coverage. Retire superseded legacy mechanisms and misleading documentation; retain history through Git and exact runtime information, not compatibility code without a need.

Final checkpoint: independent integrated review, human confirmation of review sufficiency and task conclusion under the task protocol. Report limitations and backlog candidates separately from unmet promised capabilities.

### Intermediate-state contract

An intermediate milestone need not be a supported mixed-mode product. Temporary coexistence or temporarily unconformed callers are implementation choices. At each checkpoint record passing new-mechanism tests, intentionally failing legacy families, unexpected failures, and the milestone at which each expected failure must pass. Identify exact tests once knowable. Do not add a compatibility layer solely to make every milestone look complete, and do not claim unfinished integration works.

## Verification coverage

Use real compiler fixtures for mechanical semantics. Controlled producers/dialogs may supply uncommon agent actions and invalid data; they exercise the mechanism, not the truth of an interpretation. Reuse repository testing conventions rather than introducing a separate production framework.

| Area | Required observations |
| --- | --- |
| Acceptance and identity | New and reused IDs; same provider key within scope; fresh IDs across scopes; duplicate/dangling/wrong-kind references rejected atomically; stable exact identity after identification withdrawal; ambiguous/historical names. |
| Organization | Add, supersede, withdraw, cross-owner reuse, declaration-only contribution, separately attributed organizing judgment, qualified inconsistency without displacement, competing uses, explicit re-adoption without reinstatement. |
| Results | Exact old selection; revised current answer; historical selection deliberately superseding current successor or forming an alternative; unchanged selected subject; no global last writer. |
| Exposure | Actual independent producer inputs; no assembly/equality/browsing exposure; content versus scoped inventory; matching additions only; known disclosures, later changes, updates before submission, partial notices, exact causes and membership. |
| Outcomes | No submission, structural failure with/without repair, valid unmet diagram requirement, reported inability, established empty result and useful partial result; valid declarations still take effect. |
| Diagrams and guidance | Explicit state-diagram request; optional illustration; compatible rendering without an illustration; qualified labels/legend; missing data versus rendering failure; two alternatives only one renderable; exact option invocation and its own result contract. |
| Application continuity | Per-Lens method/selection rules, exact Projection and paging, composite/support identity, zero new inference on exact presentation, retained outcome reuse, direct/worker parity and reference lifetime. |

Implement and test these agent instructions: honor result contracts; reuse identities deliberately; ground and qualify claims; acquire complete targeted content, qualifications and support before displacement; distinguish additions/supersessions/withdrawals; report inconsistency at precise claim/use endpoints; preserve original ownership and applicable qualifications when reusing or partitioning; redesignate the earlier answer actually being revised; consider substantive updates delivered during the dialog; and author owner-specific follow-up options and illustrations with exact references. Preserve evidence-access and source-as-data instructions.

Focused live trials inspect instruction usability as well as integration. Observe whether an agent requests needed information, qualifies unsupported claims and targets the intended uses. Allow valid variation in wording, local keys, decomposition and diagram structure. Do not assert one golden answer, exact picture, statistical compliance or architectural correctness. Record enough inputs, instruction/model versions and observed behavior to explain findings. Optional omissions are not failures unless explicitly requested; controlled dialogs cover all required mechanism cases.

## Requirements, implementation choices and risks

| Settled requirement | Delegated implementation choice |
| --- | --- |
| Stable identity, exact declarations, qualification and atomic acceptance | Record layout, indexes, IDs, serializers and schema organization. |
| Actual exposure and explicit scoped selection coverage | Acquisition tools, pagination and bounds with truthful omission reporting. |
| Producer boundary and all-family migration | Adapters, internal module structure and transition sequencing within milestones. |
| One supported state diagram with retained meaning | Renderer library/layout, detailed schema and catalogue packaging. |
| Complete qualified application access and exact continuity | Direct engine records or mapped application values preserving exact traceability. |
| Controlled coverage plus focused live trials | Harness, scenario grouping and run counts. |

The implementing agent owns recording evidence at the early slice and final checkpoints; the human planning/product owner decides consequential changes. In particular:

- Baseline identification scopes can generate broad addition warnings, especially changed-method batches for many existing Entities. Preserve representative causes and scope; do not disable them to reduce noise.
- Exact acquisition does not capture semantic dependence on unknown later information. An added waiting case may matter to an earlier inference that never acquired a relevant inventory. Record concrete examples; broken agreed propagation is a defect, broader inference is deferred.
- Semantic acquisition is an agent instruction, not mechanically enforced understanding. Live failures may justify instruction repair or a separately approved enforcement design, not an implicit completeness gate.
- Common packaging must not flatten epistemological guarantees, invent mechanical exposure or silently restore withdrawn information on a cache miss.
- Full migration can expose contract mismatches. Raise meaningful conflicts with accepted answer identity, provider guarantees or outcome behavior rather than silently choosing a weaker rule.

There are no intentionally unresolved consequential design choices required before implementation. Detailed contracts and interfaces are implementer-owned within the decisions. A newly discovered semantic conflict goes to the human before the affected change; lack of evidence leaves the settled policy and deferrals intact. Review observations are not a standing monitoring service or required user-value study.
