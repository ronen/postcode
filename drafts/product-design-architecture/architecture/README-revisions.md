## Implemented subset of the product model

The [coordinated-Views decision](../decisions/coordinated-views-and-qualified-results.md) allows a Presentation to coordinate several independently qualified Projections and a Projection to concern several captured program states. The current CLI implements a narrower shape: one configured project under the unchanged-input session contract, family-specific construction and a single top-level Projection descriptor per program View. Embedded module bases and associated-inspection selections are specific compositions within that implementation, not a general facility for coordinating arbitrary Projections.

The existing construction/arrangement boundary remains applicable to each input. Core supplies selected qualified content and any qualified population summaries; arrangement describes the supplied populations and applies display choices. A display count or a count of omitted items does not independently establish project-wide coverage. New program claims remain core analysis responsibilities.

The CLI does not follow changing inputs, persist workspaces or offer multi-state analysis. It invalidates on detected relevant changes and requires reopening. Retained results remain immutable; later requests can select new interpretation and correction/association snapshots. These selections support the answer but are distinct from its captured program-state basis, and do not acquire following or pinned policies.

There is no public request for redisplaying a specified retained Projection, so current paging and format commands may reselect. This is the known F6 human-facing continuity/disclosure limitation: separate commands and changed Projection IDs in JSON do not adequately disclose refresh to a human paging an answer. Presentation-only actions are intended to preserve the selected answer; an interaction that refreshes must make that behavior apparent and disclose consequential changes in the answer, selection or qualifications. Exact retained-Projection presentation with new presentation inputs is the implementation direction. Clearly disclosed reselection could be an interim treatment but would not provide equivalent continuity. Remediation is explicitly deferred in the [retained-Projection View backlog entry](../backlog.md#allow-a-view-to-be-requested-for-an-existing-projection); conceptual adoption does not implement it.

Coordinating several Projections from an existing Session does not inherently require multi-state support. Input attribution, composition recording, presentation continuity and interface compatibility must be addressed for that capability; additional captures require their own state, identity and session-scope decisions.

Current observation batches retain the presented View, rendered output, session identifier, configured paths and method names, but do not generally export the captured program-state basis associated with the Projection. For example, ordinary module inventory omits the retained analysis-input support; source-detail output can include individual evidence digests without establishing a complete captured-state association. Retained core support and exported observation provenance are different guarantees. This is a [known current recording gap](../decisions/coordinated-views-and-qualified-results.md#current-observation-provenance-gap), not only a future multi-state requirement.

The product permits a summary suggestion when no more specific information need has been expressed; it does not require a summary-first default. The current no-argument CLI command lists modules, and `summarize` requests the implemented module interpretation. This is compatible with the optional suggestion, although the CLI does not provide a general summary View selector. Adoption of the conceptual model changes neither command behavior nor the current schema and identity contracts.
