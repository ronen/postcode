# Qualified construction under the request model

Status: in preparation
Arising from: [Explicit Lenses and qualified request resolution](../plans/lens-request-model.md)
Scope: module, organization, dependency and investigation qualified construction, retained support, arrangement, identity and reporting
Supersedes: [Separate qualified Projection construction from presentation shaping](qualified-projection-construction.md), the complete record, jointly with [Lens application and request outcomes](lens-application-and-request-outcomes.md) and [Experimental structured outputs](experimental-structured-outputs.md).

## Context

Separating designation and unsuccessful request resolution from Lens answers changes retention, identity and reporting prescriptions distributed across all three headed decisions in qualified construction. Whole headed decisions are the units of supersession. This record carries forward their unaffected commitments and identifies the complete replacements; the earlier text remains historical evidence.

## Decisions

### Preserve qualified construction and arrangement isolation

#### Decision

Interface-independent core owns selection of qualified subjects, relationships, revision semantics and population summaries, and construction of addressable immutable answers from materialized information and outcomes. Presentation owns arrangement into rows, labels, excerpts, pages, omissions and source disclosure, then format-specific rendering. Core does not import CLI View types or terminal-layout helpers.

For the existing builders use typed immutable, eagerly resolved content values exposing selected records, full Claim contexts, captured support and relevant evaluation outcomes with their attribution. These values are internal representations, not separately stored pipeline stages or CLI JSON schemas. Construction consumes materialized records without analysis, source-file reads or display bounds. Construction and arrangement remain independently callable even if a coordinating builder remains.

Every Presentation of these families, including future interfaces, arranges supplied qualified information without independently querying accumulated state to broaden or refresh it. New information returns through coordination, Evaluation and core construction. Eager resolution is a current-builder strategy, not a universal prohibition on projection-scoped lazy materialization or presentation pushdown. Such execution preserves meaning, population, qualification, materialization and retained-result semantics; rendering never initiates Evaluation. Presentation standard expansions are declared before Evaluation.

Organization artifact summaries identify their group, materialized artifact/module/documentation-association support population, contributing Claims/contexts, repository/module evaluations, placement outcome and detail state. They are qualified aggregations, not independent Claims about file content or the entire repository. With partial placement, `moduleAssociated` counts only established associations; the legacy `unanalyzed` remainder is materialized artifacts with no supplied module/documentation association, not proof those associations do not exist. `opaqueBoundaries` counts captured boundary markers within that same remainder.

Classification is complete only when the relevant artifact support including documentation associations, module population and placement are available and fully materialized by completed evaluation for the scope. `detail: materialized` does not itself establish completeness. `detail: not-requested` remains distinct from empty or incomplete classification, even if compatibility fields contain zero. The common core predicate remains reproducible from explicit detail/evaluation fields in the self-sufficient arranged View: materialized detail and applicable, available, completed, fully materialized repository and placement outcomes. Extend explicit qualification if future inputs no longer cover that predicate; do not add an unexplained hidden arrangement flag. Complete classification still carries capture limitations.

Preserve the existing opening materialization summary and complete-case wording. In incomplete classification, inspection says `Other captured artifacts: N · M opaque boundaries (classification incomplete)`; a shown tree count says `N other captured artifacts (classification incomplete)`; the closing explanation says that these artifacts have no module/documentation association established in supplied information and classification is incomplete, retaining configured-project scope. Apply that closing qualification when any requested classification is incomplete, independently of displayed module count. For valid population answers with no selected groups, use the conservative repository/placement qualification without inventing a group classification. Unsuccessful lookups instead return the same relevant basis limitation in their resolution information. Preserve existing numeric calculations and the documented qualified meaning of `unanalyzed`; no count implies complete analysis.

Investigation content supplies ordered original-to-selected root and child/accompanying-correction relations, parent/role, displaced composition/corrections, correction-to-provenance, navigation and exposure per `(evidence, provenance)` pair. Keep incoming entries even when several originals select the same primary. Shared adjacency cannot lose traversal order. The unpaged domain revision result owns neither the 24-row revision page nor eight-item cause-path display bound. Investigator-context delivery retains its separate bounds, correction eligibility and exposure rules.

Arrangement preserves the existing 256-account queue and duplicate behavior: displaced information is added only for entries passing the bound; corrections come from shown accounts and the current revision page; provenance comes from those accounts/corrections and shown inconsistency reporters. Build support from that displayed subset and filter exposure pairs to collected provenances in insertion order. Source detail and binding requests follow that subset. Passing all resolved provenance through would change the meaning of displayed exposure. Mechanical inspection plus associated selection remains a core answer, not an identity reconstructed from a bounded listing.

#### Reference binding and disclosure

Request coordination owns the Session binding service. For valid applications preserve the established allocation schedule and each call's population/order:

- Subject lookup coordinates the relevant investigram population or module/group populations before construction. Read-only classification of an already-bound reference does not allocate unrelated subjects.
- Mechanical construction coordinates module discovery, organization groups then modules, and dependency module-basis populations, supplying bindings for embedded module arrangement too.
- Investigation arrangement requests references in bounded traversal/revision-page order, then navigable module subjects and any supplied candidates.
- Associated listing binds all matches, including off-page matches, after mechanical/investigation allocations and before continuation lookup/page arrangement.

The arrangement port binds only explicit core-supplied IDs with validated module/group/investigram kinds. Its allowed population includes selected/reachable accounts, displaced originals and descendants, association matches; revision primaries, targets, replacements, reporters and complete cause `via` lists; inconsistency and displaced-correction participants; composition parents, investigation subjects and supplied mechanical/candidate populations. Claim/evidence IDs remain precise references rather than compact-bindable entities. Validate the entire binding request before allocation. The allowed population is not a requirement to preallocate it.

The port exposes no selector lookup, enumeration, retrieval, Evaluation or refresh. Bindings remain append-only; mutable binding services and compact spellings do not enter retained Projection payloads. Preserve collision behavior and population-wide mechanical/association allocation rather than shrinking it to displayed rows. Eager resolution must not allocate every possible investigation reference. Parent rendering/finalization has no binding capability. Resolution-result candidate bindings are coordinated from the explicit returned population and obey the same kind/lifetime rules.

Holding resolved support internally is not source disclosure. Classify and record actual exposed source after arrangement, including expansions/exports, in every interface. New source fields require classification coverage. Resolution/usage reporting does not become an unclassified source-export path: source-bearing qualified content is presented through its appropriate View; non-View results carry the bounded request, reason and reference information required by their contract.

#### Rationale and consequences

Core selection and presentation change for different reasons. These boundaries preserve fixed answers without restricting ordinary layout or legitimate qualified execution optimization. JSON Views are bounded Presentations, not substitutes for full core content. A read-only store would still let arrangement broaden an answer; the binding-only capability is the narrower required interaction. Sharing immutable support and indexing selected bases avoids duplication without adding a stored content/View/text stage or speculative cache infrastructure.

### Preserve retained selections and support under the new outcome contract

#### Decision

Use the [family-specific outcome table](lens-application-and-request-outcomes.md#return-unsettled-applications-as-resolution-results) for which applications retain Projections. Retain valid empty/partial/unavailable mechanical answers, valid interpretive accepted/limited/failed/unavailable selections, exact existing investigram inspection and associated inspection including zero matches. Unsettled explicit lookups and usage no longer create the old selection/descriptor artifacts.

For retained interpretation selections, store the full derived, unpaged revision result at construction, rather than reconstructing it from a history watermark or an assumed sufficient evidence closure. Derivation includes correction acceptance order, citation propagation and provenance exemptions for selected originals/primaries, reachable composition/accompanying accounts, displaced originals with every composition descendant, and associated matches. Gather corrections from displaced descendants as well as roots. Preserve primary/family-primary, conflict, reconsideration, every ordered revision row with complete proximal `via` lists, qualified inconsistencies and reporter/ordinal attribution. These lists do not claim all possible citation paths.

Retain ordered roots/selection relations, displaced and navigation relations whose derivation depends on accumulated history. Refer to immutable accounts, corrections, provenance, Claims/contexts and evidence rather than duplicating their bodies. Relative correction order is stored through derived rows and selected primaries, not absolute Session counters. Old reconstruction reads frozen snapshots/references without rerunning current revision derivation or discovering new associations.

Module-only inspection routed through organization uses the displayed embedded module Projection as its associated mechanical basis, with the selected module subjects. Group/mixed inspection uses its displayed organization basis and selected groups/modules. Exact originals never silently redirect to replacements.

Retained selection records identify Session and versioned construction method, variant, Lens, subjects/true parameters, answer-relevant status, relevant Evaluation or immutable unavailable outcome, any mechanical basis, ordered associations and frozen derived values. Validate reference kinds and same-Session membership, and retain atomically. Every retained field participates in or is determined by semantic identity inputs. Attempt reporting IDs are not automatically retained-record references; usage and reuse status remain reporting. Preserve accepted Evaluation provenance. Inline unavailable selections retain kind/code/diagnostic, while provider status/body/request ID remain invocation reporting and cannot alter the answer identity alone. The store's investigation-evaluation index includes only evaluations, so retaining an unavailable selection cannot suppress an eligible retry.

#### Rationale and consequences

Storing the mutable-history-dependent selection and its already-needed derived result is a bounded retention choice. A watermark either changes identity on irrelevant additions or permits conflicting payloads; a reduced closure requires an additional replay-sufficiency proof. Neither is needed here. Compatible reuse, atomic acceptance, exact-original access, failure taxonomy, cancellation and evidence lifetimes remain governed by the accepted execution/interpretation decisions.

### Separate answer, View and report identity

#### Decision

The [effective answer inputs](lens-application-and-request-outcomes.md#give-equivalent-qualified-answers-repeatable-identity) define Projection identity. Use Session-scoped identity and the responsible identity-method version. Change all designation-bearing formulas and update responsible methods; do not insert per-invocation attribution into shared answer payloads or reusable work identity.

For the current families the replacement formulas have these semantic inputs, with explicit kind-aware reference normalization:

| Result | Identity inputs and change |
| --- | --- |
| Module Projection | Versioned construction method, resolved selected subjects or population subject, Lens/normalized parameters and full qualified answer support. Remove literal/reference designation and lookup-only status from the payload/key. |
| Organization Projection | The same rule with repository/project population meaning, group/module selections, embedded module basis and qualified layout/placement detail. |
| Dependency Projection | The same rule with direction, selected subjects, dependency/module/organization bases, graph/relationships, occurrences/non-edges, recognition coverage and opaque-subject qualification. |
| Investigation/associated Projection | Full retained semantic payload under the new request separation, including the exact retained outcome and frozen interpretation/revision/association selections and mechanical basis. Remove designation; retain valid unavailable selection kind/code/diagnostic. |
| Module, organization and dependency View | Presentation method + retained Projection ID + effective presentation choices + consequential supplied resolution context actually exposed by that arranged artifact. This explicitly replaces the old Projection-ID/presentation/method-only formulas. |
| Investigation arrangement key | Presentation method + retained Projection ID + format/source choices + normalized continuation/revision page + reference lifetime + exposed consequential resolution context and invocation reporting, including reuse, attempt and provider outcome details. |
| Final investigation View | Presentation method + usage-independent arrangement key + authoritative usage. |
| Associated-inspection View | Presentation method + associated Projection ID + base mechanical View ID + normalized association continuation + reference lifetime + any exposed resolution context not already determined by those inputs. |
| Resolution result and usage report | No semantic/content ID or Session-addressable report object is required. The request/attempt correlation and existing batch-local observation artifact/event UUIDs identify occurrences, not repeatable program answers. Removing the usage descriptor removes its identity input entirely; non-View usage rendering/finalization does not fabricate an arrangement Projection. |

“Exposed context” means data included in the arranged artifact, including its structured representation, not every field on the invocation. Consequential differences cannot collide, but hidden/incidental routing cannot change answer identity. Preserve the raw supplied request in request reporting independently. Do not define one universal View identity formula for future Presentations.

Continuation normalization remains: absent/null is no continuation; a token resolving in the frozen supplied association population contributes its precise normalized record reference; an unknown token contributes a literal in a disjoint key space. Do not hash resolved compact spellings or perform fresh Session lookup. Preserve raw continuation in request/output where currently exposed. Omitted revision page normalizes to 1. Pages, formats, source choices, lifetimes, usage and invocation reporting do not alter Projection identity, even for empty or unknown pages.

Carry the investigation usage-independent arrangement key explicitly in the internal worker result envelope, not public JSON or reconstruction from bounded displayed data. The parent replaces provisional usage using that key, recomputes the final View ID and re-renders self-sufficient content without core lookup, binding or selection. Repeated finalization with the same usage is stable. Resolution results and usage reports travel as explicit non-View alternatives with the same authoritative usage and delivery checks; they need no faux Projection key.

Keep the shared mechanical presentation method rather than introducing an organization-specific version solely for this change. Bump each affected Projection/presentation method from the implementation baseline when its semantics change; do not replay historical version numbers. The provider currently captures the method registry in analysis-inputs, so method changes can also change input-record references. Preserve other captured values and qualification and account for that provenance effect explicitly. Entity bindings and investigram identity semantics are unchanged.

#### Rationale and consequences

Separating designation from answer identity must not merge distinct displayed resolution explanations. Explicit arrangement inputs preserve this distinction through parent-side finalization. Event identity suffices for reports without introducing new retained referents. Text/JSON shapes follow the [experimental-output policy](experimental-structured-outputs.md), while semantic preservation, source disclosure and failure behavior remain requirements.

### Preserve verification obligations for the changed cases

#### Decision

Verify every row of the replacement outcome table, including missing-to-bound resolution without mutation/collision and retained reconstruction after later correction/association work. Cover identical reinsertion, irrelevant insertions changing absolute ranks but not relative order, transitive causes, whole-evaluation exemptions, competing correction branches, later descendants, inconsistency reporters, exact originals and displaced composition. Preserve bounded investigator context as well as CLI pagination and the correct associated mechanical basis.

Verify arrangement without store access; binding rejection before partial allocation; complete typed reference populations, including off-page support; allocation sequence/collisions; actual source classification; qualified subset versus evaluation-wide totals; empty, partial/unavailable and unrequested detail. Compare full core content with beyond-bound display omissions and displayed-subset provenance/exposure.

Compare fresh, accumulating and reordered Unicode/JSON/observation runs. Make intentional method, identity, request/outcome and output changes explicit rather than discarding fields to make comparisons pass. Check incomplete artifact placement with some displayed modules, incomplete artifact support with completed placement, neutral labels/adjacent notices/conservative closing qualification, complete-case wording and reproduction of classification from explicit detail/evaluation fields. Preserve numeric calculations and qualifications under renamed descriptors.

Check same-answer/different-presentation identity; empty/unknown pages; normalized continuations across reordered compact bindings; first execution versus reuse; and actual usage changing final View identity without changing Projection or arrangement identity. Verify stable repeated finalization and immutable-payload consistency. The permitted visible changes are the request-model corrections, explicit retention/identity/report changes and directly affected experimental shapes described in these replacement decisions. Other consequential visible changes still require human agreement.

#### Consequences

The original construction-separation work's implementation/promotion sequencing is historical and complete. Its established construction/binding/disclosure boundaries continue to apply now. New request-model contracts are adopted with the implementation plan; conformance to those additions is established by that plan's verification, not asserted by document adoption. There is no exemption for existing builders at completion, and future Presentations inherit the semantic boundaries without inheriting CLI-specific eager execution or display limits.
