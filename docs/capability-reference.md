# Capability reference

This describes supported internal application behavior, not architectural priority
or a public API promise. The [application specification](app-specification.md)
governs intended behavior. The [application entry](architecture/README.md#application-entry)
returns complete qualified content; [CLI access](cli-reference.md) is authentication
and help only. There is currently no human investigation interface.

## Common contribution capabilities

Mechanical module, symbol, export, dependency and organization findings use the
common contribution ledger. Agentic accounts retain owned items, associations,
result designations and actual producer inputs. Fresh selections show displacement,
inconsistency and reconsideration causes; exact retained answers preserve their
captured support and status. Interpretations remain qualified accounts, not established
program truth. Reconsideration identifies changes to received information, not error.

<a id="mechanical-exploration"></a>
## Mechanical exploration

Requests use `{ kind: 'lens', lens, designation }` with supported parameters and
optional expansion requirements. These names are internal Lens identities.

| Lens | Information requested | Scope and limits |
| --- | --- | --- |
| `modules` | Module inventory | Configured TypeScript population, including qualified external interfaces; not a whole-repository account. |
| `organization` | Project or repository group organization | A navigation scheme with qualified placement and artifact classification, not canonical architectural decomposition. |
| `inspect` | Selected module/group detail and associated retained accounts | Exact names/generated module handles may be missing or ambiguous; exact references identify retained subjects. |
| `dependency-structure` | Dependency structure and cycles | Recognition, ownership and resolution coverage remain explicit; external interiors remain opaque. |
| `dependency-children`, `dependency-parents` | Outgoing or incoming module dependencies | Direction concerns dependency relations, not universal containment. |

Exports, documentation, composition and group/dependency organization expansions
retain their own outcomes. Unavailable or incomplete information does not establish
an empty population. Recorded documentation remains an assertion. The internal
exports fixture Lens exercises a separate qualified export-surface contract; it is
not a public command or dynamically installed extension.

<a id="interpretive-investigation"></a>
## Interpretive investigation

| Lens | Meaning | Subject |
| --- | --- | --- |
| `summarize` | Terse qualified functional account | One module |
| `explain` | Clarify selected content | Exact retained contribution, item/component or designation |
| `decompose` | Finer selectable aspects without an exhaustive/disjoint partition claim | Exact retained content |
| `examine` | Deeper investigation, including limitations or contrary findings | Exact retained content |
| `state-behavior` | Qualified state-dependent behavior and declared diagram result | One module |
| `follow-up` | Execute an owner's retained proposed question | Exact contribution and `parameters: { option: key }` |

Supported exact selections use `designation: { kind: 'selection', subject }`.
Invalid, foreign or unsupported selections are refused before investigator invocation.
A diagram-contract failure does not erase valid account information. Qualified
follow-up preserves the earlier content actually supplied, provenance and delivery
limits; it does not accept arbitrary earlier Projections as general inputs.

Ordinary requests can reuse retained outcomes; `fresh: true` explicitly requests
another investigation. Completed failures/stops can be reused; communication or
configuration failures remain retryable. Attempt reporting stays separate from
selected answer meaning. Hosted work requires explicit route selection and
transmission enablement; [setup](hosted-investigation.md) describes credentials,
billing routes, disclosure and cancellation limits.

<a id="presentation-and-operational-facilities"></a>
## Exact access and operational facilities

`{ kind: 'present', target: answer.id }` retrieves an exact retained answer and its
fixed support without new selection, evaluation, acquisition or inference. It returns
content, not a rendered View. Unknown, foreign and unsupported retained targets
remain distinct refusals. Names and precise references share answer identity when
their settled subjects, question, parameters and support agree. Compact aliases and
`@`-prefixed reference syntax are removed; precise references belong to their Session.

Usage reporting is subjectless and performs no inference. Request attribution
separates prerequisites, investigator-triggered evidence, retained consumption and
new production. Availability of work/usage reports does not establish research
recording, navigation-origin history or complete captured-basis export.

Direct trial support arranges qualified explanations and SVG/text diagrams from
supplied content only. Each standalone diagram carries its alternative's interpretation
status and applicable owner limitations. Incompatible and unrendered alternatives
remain disclosed. Mechanical-family human Views, paging/terminal output, observation
sinks and feedback builders have retired. No replacement research facility is wired
to trials; see the [research-support gap](backlog.md#research-observation-and-feedback-after-cli-retirement).

The internal shared Presentation negotiation contract remains available for declared
consumers and useful expansion selection, with tests for compatibility and exact
support. It has lost its principal client; no production renderer was added to
justify retaining it. Its later separation is a design residual.

<a id="scope-of-this-reference"></a>
## Scope of this reference

The application is single-project, transient and in-process. Input invalidation,
interruption and close terminate further requests. Execution is cooperative, with
separate shutdown assessment; see [lifecycle](architecture/README.md#application-entry).
There is no GUI Workspace, persistence, general multi-Projection composition,
multi-state analysis or public transport. Other research Lens families remain
possibilities rather than delivered capabilities.
