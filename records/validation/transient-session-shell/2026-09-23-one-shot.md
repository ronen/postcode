## Implemented checkpoint

One-shot commands open one configured project in a transient session, execute one
view request, submit its observation, and close the session. The request boundary
owns the provider and ProgramRecordStore. Session UUIDs are independent of input
support; provider claim contexts retain separate immutable analysis-input records,
source evidence and responsible methods. Store validation retains session ownership,
record immutability and reference-kind checks.

Snapshot records, snapshot parameters and generated next-command presentation
fields are removed. Exact name/handle lookup preserves all matches. One-shot IDs
cannot select an earlier invocation's entity. Library projections can select a
precise reference within an existing session. Experimental view schemas and
observation format are version 1; batches carry the producing session and command
ordinal, with independent observation UUIDs.

This is an intermediate checkpoint, not the complete shell. The executor rejects
a second request. Accumulation, a growth-safe reference allocator, continuing-session
change detection, shell lifecycle, failed-command observations and shell ambiguity
recovery remain for subsequent stages. No public stdin/file execution was added.

## Before/after semantic comparison

`scripts/compare-session-conversion.mjs` compared the original build with this
checkpoint on fresh temporary Git copies of `dependency-journey`,
`dependency-contract`, and `exports`. All 54 view comparisons passed: nine requests
in Unicode and JSON on each fixture (modules, both organization subjects,
inspection with/without source, dependency structure with/without source, and
direct children/parents with source).

The comparator checks a bijection of record and compact references, preserving
repeated-reference relationships rather than redacting identifiers. It checks
populations, relationships, qualification, source evidence, omissions, and
presentation ordering. Unicode output is also compared through that mapping,
allowing the intended context-header and generated-command/footer changes.
Schema versions and old/new selector-mode fields are explicitly adapted.
Containment-support arrays and organization source-evidence collections are
matched without relying on their former snapshot-derived hash order. Evidence
records are paired by all their fields under the same reference bijection; no
supporting claim or reference is dropped. This is an intentional ordering
difference in supporting collections, not a normalization of presentation rows
or displayed relationships, whose ordering remains checked. A repeated run on
new temporary paths exposed this second supporting-collection case; the verifier
was corrected before the review handoff.

The comparison also checks actual output recorded in each observation, source
escape event types, and the new session/command correlation. These are controlled
migration checks, not a historical-input validation or general comparison feature.

Reproduce after building both revisions:

```sh
node scripts/compare-session-conversion.mjs BEFORE_BUILD AFTER_BUILD REPORT.json
```

Each build directory must contain `src/lib/cli.js` and resolve the pinned
TypeScript package. The script creates and removes its temporary input repositories.

## Real-compiler interruption experiment

`scripts/probe-compiler-interruption.mjs` runs the real CLI path on a generated
80,000-declaration TypeScript source. Its child reports a source read from the
actual compiler host (verified by stack), then proceeds with synchronous compiler
work. A control run completes; the parent signals the interrupted run 20 ms after
that marker. No asynchronous analysis stand-in is involved.

| Run | Result | Elapsed | Signal to exit |
| --- | --- | --- | --- |
| Control | View published; exit 0 | 1,360 ms | — |
| Interrupted | Native SIGINT termination; no view or completion event | 662 ms | 15 ms |

This verifies process termination during compiler-backed work as an available
fallback. It does not verify return to a prompt, safe partial-state continuation,
or interruption observation delivery. The shell stage must choose and verify
its execution/observation arrangement; this checkpoint adds no JavaScript signal
handler that would wait on the blocked compiler event loop.

Reproduce with `npm run build` followed by
`node scripts/probe-compiler-interruption.mjs`. Its temporary project is removed.
Timings are observations, not test thresholds.

## PostCode smoke checks and limits

The implementing agent inspected Unicode module inventory, dependency structure,
and `inspect session --source-detail` on PostCode. All returned exit 0. Inventory
reported 208 modules (52 project, 156 collapsed external); dependency structure
retained 310 relationships and disclosed its Unicode omission bounds and partial
organization expansion. Inspection selected one module and disclosed captured
locations/excerpts with a source-escape event. Each batch had command ordinal 1.
This is agent inspection; human inspection of the complete adaptive investigation
remains in the later plan stages.

These three independent short-lived sessions ran sequentially in one warm Node
process with an in-memory accepting observation sink: approximately 5.09 s,
3.64 s, and 3.38 s respectively. They establish no follow-up reuse benefit.
Process peak RSS increased from about 411 MiB after the first run to 856 MiB after
the third without forced garbage collection. This is a process high-water mark,
not a measurement of live retained session state or a memory limit. Representative
accumulating-session cost and memory measurements remain outstanding.

No real-project observation files or source-detail transcripts are included in
this report. Unchanged-input assumptions remain explicit. Meaningful continuing-session
invalidation is deliberately not claimed at the one-shot review checkpoint.
