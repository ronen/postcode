## Controlled filesystem model

The preserved [model](m3-round-2-case-model.mjs) replaces filesystem calls within a
standalone process with a directory tree carrying explicit case rules, device IDs,
inode IDs and symbolic-link targets. Its lookup semantics apply each containing
directory's own rule. The production `outputBoundary` implementation supplies the
actual results; the fixture supplies the expected result. This demonstrates logic
errors under the modeled rules, not native support or certification.

The [checkpoint results](m3-round-2-case-model-result.json) preserve these cases:

| Insensitive directory and sensitive directory share a device; missing output suffix differs in case | Insensitive equivalent is excluded | Equivalent is missed at this checkpoint |

| Device-root listing contains a child deleted before inspection, plus a usable child | Boundary established | Established, count 1 |

Running the first three cases against the reviewed baseline also confirms the two
review concerns: mixed-filesystem sibling exclusion is wrong there; its cached
insensitive device flag excludes the sensitive sibling incorrectly. The local
correction changes which per-directory case is wrong without resolving that
assumption. This is explicitly pending, not counted as a successful correction.
