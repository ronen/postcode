@investigram-72904a46 · interpretation
`fsm-engine` implements the public typed FSM factory and each machine's runtime. `define()` delegates DSL capture/validation/compilation, then returns factories whose instances share the compiled definition but keep separate context, state, FIFO event queue, tracing state, and timers. Dispatch is synchronous at the outermost call and queue-based when re-entered: it tries state-specific begin actions and ordered guarded transitions, then fallback handling; known handlers with no matching guard imply a no-op stay, while unknown or wholly unhandled events raise dedicated errors. External transitions run exit actions, transition actions, commit state, then entry actions; internal transitions run only transition actions. The module also exposes trace logging and the action-facing dispatch/timer controls.
