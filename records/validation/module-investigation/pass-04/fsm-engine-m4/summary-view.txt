Module @module-28ee01f8: fsm-engine

@investigram-dc111a38 · interpretation
Implements the stateful FSM instance and its typed factory. `define` delegates DSL capture, validation and table compilation to `FsmBuilderImpl`, then factories share that immutable-looking definition while each instance owns context, current state, FIFO event queue, timers and tracing state. Dispatch is synchronous at the outer call and re-entrant calls only enqueue; processing runs state begin actions, first matching guarded transition, then fallback handling, with an implicit stay when handlers exist but no guard matches. External transitions run exit, transition and entry actions, committing the target between transition and entry actions; internal transitions run only transition actions. Unknown events and known-but-unhandled events are distinct errors; any thrown guard/action/error clears queued events. Initial entry actions run during construction. The action API loops dispatch back into the queue and delegates keyed scheduling/cancellation to `TimerRegistry`; trace output records events, guards, transitions and actions. The README describes these broad semantics, but its timer-payload promise conflicts with the implementation: the adapter appears to pass no payload argument when `payload` is present and one `undefined` argument when it is absent.
