@investigram-026d2d6e · interpretation
`dispatch` serializes work through a synchronous FIFO: re-entrant dispatches enqueue and return, while the outer call drains the queue and clears pending work on failure. For each event it rejects unknown names, runs state-specific begin actions, chooses the first transition whose guards all pass, then tries fallback begins/transitions. External transitions run exit, transition, and entry actions around the state change; internal transitions run actions without changing state. Known events with transitions but no passing guard count as an implicit stay; events with no applicable handler raise an unhandled-event error.
