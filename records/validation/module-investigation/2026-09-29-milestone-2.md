## Behavioral evidence

| Boundary | Verified behavior |
| --- | --- |
| Operation selection | Exact operation/subject/semantic-parameter identity reuses outcomes independently of presentation and consuming lens; no new dialogue or usage on repeated display. |
| Atomic retention | Successful roots, children, provenance and accompanying corrections are retained together. Invalid submitted correction trees retain only failure, leaving earlier accounts unchanged. |
| Successive evaluation | Direct session operations use earlier retained context, record complete correction eligibility and retain later replacements without mutating original composition. |
| Shell journey | Summary, repeat display, exact child inspection, captured source detail and usage run through the in-process CLI and production worker with injected terminal input and captured observations. |
| Correction journey | A second module summary retrieves an earlier account, reports a qualified correction, and exposes references that inspect the original and replacement independently in that shell. |
| Selection | Missing/ambiguous module selections do not invoke investigation; ambiguous candidates expose exact module references. Foreign investigram references are unknown in a fresh session. |
| Outcome policy | Refusal, unrecovered truncation, malformed replies, invalid submissions and guard stops are retained. Communication/configuration failures preserve diagnostics/usage but permit a later new attempt. |
| Interruption | Active worker interruption aborts/closes the parent dialogue and suppresses result publication. Received usage and dispatched source exposure survive in final reporting and observations. |
| Invalidation | A source change during submission invalidates the session and suppresses the result while preserving attempt usage and invalidated termination. |
| Late completion | Replies and usage received after guard termination/closed dialogue cannot publish interpretation or alter reported usage. |
| Usage | Actual calls are counted once; original attempt and session usage remain attributable. Unknown/anomalous reports and synthetic/provider origins are distinct. Aggregate overflow is unknown, and non-finite raw values remain distinguishable after JSON serialization. |
| Views and observations | One-shot references disclose expiry. Generated terminal controls are escaped. Investigator source reads alone produce no human source-escape event; explicit support inspection does. Support exposure remains attributable to the account or correction's generating provenance. |

The reusable `ScriptedInvestigator` replaces the communication participant only.
Evaluation, evidence acquisition, coordination, acceptance, record-store retention,
selection, worker messaging, command parsing and publication are production code.
The CLI environment's internal injection reaches the parent communication
participant for each fresh worker-coordinated dialogue. It does not add a public
command flag, alternate input protocol or filesystem access for the investigator.

## Reproduction

From the repository root:

```sh
npm run check
npm test
```

For the focused integration journeys after building:

```sh
node --test _build/test/investigation-integration.test.js
node --test _build/test/execution-ownership.test.js
```

The tests construct temporary configured projects, supply deterministic exchanges
through `test/investigator-double.ts`, and clean their fixture directories. Shell
journeys supply a terminal-like stream to `runCli`, drive commands from captured
views/observations, and preserve actual command parsing and the compiler worker.
They use synthetic usage and no credentials.

## Residual uncertainty and acceptance boundary

**Validation remains qualified by the unresolved execution-ownership cancellation
concern accepted for deferral during milestone 1.** Previous full-suite runs
cancelled 13 tests with pending-promise/event-loop resolution, including on the
pre-implementation baseline; isolated runs passed. The
[backlog entry](../../../docs/backlog.md#diagnose-execution-ownership-cancellations-in-full-suite-runs)
contains the reproduction commands, baseline commit, affected tests and captured
results. These integration changes do not diagnose that historical intermittency.
Later passing suite runs do not erase the concern. The reviewer should assess
whether it affects acceptance of the changed worker/session integration.

Scripted exchanges establish orchestration and invariants, not provider behavior
or interpretive usefulness. Abort signals and local worker disposal do not prove
remote provider work or billing stopped. The parent retains the last dispatched
exposure snapshot and usage it actually received; later reports are ignored and
missing reports remain unknown. No retained result is reconstructed from
observations. Source stability remains the existing best-effort, non-atomic
captured-input contract.
