## Findings and their limits

### Documentation discovery versus reconciliation

The focused run acquired its README without intervention. Its rejected draft
correctly contrasts the attributed pure/stateless assertion with the counter,
qualifies proximity as insufficient for applicability, and notes the README's
explicit reference to the entry API. However, its `inconsistencies.targets` names
a repository artifact and a module. Domain validation requires earlier
investigrams and atomically rejects the whole result.

The frozen operation instructions and tool schema list the inconsistency fields
without stating that target restriction. They explain the earlier-investigram
restriction for corrections, which is a different field. This is a plausible
instruction-contract contributor to the failure, not a demonstrated model-only
limitation. The accepted domain meaning has not changed. A potential next bounded
correction is to explain that documentation-versus-implementation discrepancies
belong in attributed prose/qualification, while structured inconsistencies target
prior investigrams. That proposal is **not implemented** pending human disposition.

The fresh view-only evaluator and source-informed assessor receive only the
failure view, not an edited or rejected account substituted for it. They identify
missing functional communication and preserve uncertainty. The implementer's
separate draft analysis above does not override that user-facing outcome.

### Exact-reference failures

Cockatiel supplies the correct Event capture identity, but one association in the
telemetry child omits two characters from it. The missing identity is outside the
attempt's retained supplied/summarized evidence, consistent with rejection.
fsm-engine repeats a module identity with two characters omitted; merge-anything

These are useful evidence of a reference-copying reliability problem. They do not
justify accepting approximate identities, silently repairing drafts, automatic
inference retries or attributing the entire problem to the model. Further bounded
offline investigation of reference presentation/validation is proposed for human
direction before choosing a consequential representation change. Source-derived
content in unaccepted drafts is not claimed as successful functional communication.
