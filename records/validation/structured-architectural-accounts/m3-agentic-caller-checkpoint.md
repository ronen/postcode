## Historical support and presentation

The partial caller implementation at `1f00938` embedded the full production in every answer owner. This was removed: a production can contain many unrelated native contributions and deliveries, so repeating it for each selected owner expands serialization and imports irrelevant batch/acceptance-order details. A representative large fixture reached V8's string-size limit. De-duplicating full productions inside each answer would still include unrelated work. The final capture retains each selected owner's production identity, producer, originating question, report, qualification and independently captured causes, plus selected exact content and resolved evidence. Full attempts remain separately retained under Session lifetime. This restores the selection boundary rather than weakening historical presentation or provenance.

Common inspection identity now keys exact immutable references and captured derived status through the existing support-identity helper. It excludes operational output-exclusion metadata and never rewrites ordinary source text as a reference. Its responsible method advances to `contribution-inspection@2`. This fixes answer semantics; no general temporary canonicalization/allocation optimization was introduced.

The CLI uses `postcode-contribution-view/1-experimental`, embeds native findings without duplicate answer headers, and carries owner/item/selected-content limitations. Inspection owner pages and status detail groups use independent fixed 24-entry pages. Unknown cursors retain failed presentation status and offer a restart. Omitted counts are explicit; every qualification page is retrievable without analysis. Recorded assertions use existing bounded text/tag presentation; native/source bodies stay internal and optional source detail supplies locations. Complete support remains in the application answer. There is no claim of a global byte limit on all alternatives, retained support or rendered prose.
