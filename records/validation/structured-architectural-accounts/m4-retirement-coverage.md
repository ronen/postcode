# M4 integrated coverage and retirement

This closes the retirement obligation in the [M3 caller inventory](m3-agentic-caller-coverage.md) and the [M1 family inventory](m1-checkpoint.md). Both M3 checkpoints are accepted; this is implementation evidence for the separate final integrated review, not its acceptance.

## Reachability and retained boundaries

Supported catalogs route all agentic capabilities through `contributions/evaluation.ts` and `dialog.ts`. The old evaluator, operation definitions, tree acceptance, correction revisions, account-context delivery, selection record/validation/resolution, associated-account arrangement and old wire schema are deleted. The native record store no longer accepts or enumerates their record types. The generic hosted transport, credentials, usage, exact native evidence codec and program-evidence provider boundaries remain.

`application/retained.ts` is the sole fixed-answer resolver. All CLI arrangement uses application-captured bindings; the obsolete revocable binding port and old `retained-presentation.ts` are deleted. Operation-scoped execution/check capabilities retain busy, expiration, invalidation and close checks. Historical runtime answers continue to own immutable selected support; no persistence or cross-version Session migration is promised.

The shared usage formatter moves to `investigation/usage-presentation.ts`. The explicit account connection check and its mocked tests use the common wire protocol. `AttemptReport` keeps actual common deliveries and supplied full program evidence; empty legacy `deliveries` and `summarizedEvidence` fields disappear. Neither native summary metadata nor an available handle becomes a full-record citation. Common content exposure remains governed by actual dispatch.

Retired development comparisons `compare-investigation-construction.mjs` and `compare-investigation-revisions.mjs` exercised the removed representation. Their historical evidence remains in Git and validation records. Current human-output and module-investigation scripts import the common renderer/instructions/protocol. Frozen historical manifests still reject instruction drift before credentials; no new inference is authorized or performed.

## Retired test inventory

The following original cases at the accepted M3 caller revision are deliberately removed with their unreachable implementation. The replacement column identifies semantic coverage, or states the adopted behavior that replaces an obsolete assertion. Test counts therefore decrease; the old test total is not a coverage target.

### `investigation.test.ts`

Common execution/evidence/atomic acceptance: `contribution-dialog`, `evidence-access`, `contributions`, `contribution-exposure`, `investigation-integration`; usage anomaly cases moved to `investigation-usage` / `contribution-dialog`. Tree/correction eligibility and whole-tree validation are replaced by explicit qualified declarations, finite membership and actual delivery; no primary correction or citation-closure gate remains.

- actual dialogue follows multiple delegation layers, acquires qualified relationships, full source and documentation
- subject-only capture has multiple mappings, exclusions, unavailable artifacts and first-observed validity
- unavailable and malformed tool requests permit continued investigation without arbitrary path reads
- full result accepts nested corrections, conflicts and inconsistencies with complete exposure; originals stay immutable
- citations distinguish bare references, excerpts, and complete content accumulated across exchanges
- acceptance itself rejects cyclic and shared composition before assigning results
- correction cannot target the identity assigned to an investigram in its own submitted unit
- oversized evidence is explicitly unavailable while the dialogue can continue
- guard covers asynchronous evidence work, provider calls, call count, tool count and volume
- input changes during dialogue invalidate before acceptance; unexpected defects are not ordinary failures
- only delivered complete target context permits corrections, including separately requested parts
- corrected initial context includes chains and competing accounts, with omissions and completeness by correction
- source captures reject forged mappings and excluded aliases remain unavailable
- malformed response and unsubmitted trees fail; post-submission validity checks are outside the generation deadline
- usage retains distinct reports and anomalies without selecting uncertain totals
- provider accounting anomalies preserve both accepted and failed investigation outcomes
- corrections associate explicit program subjects through follow-ups and subordinate accounts
- correction reasons cite their reporter without granting complete account context
- corrected subjects permit entities and artifacts but reject claims and evidence
- hosted reference compaction cannot bypass the canonical decoded-reply character guard
- real evidence queries and retained investigram context encode without canonical reference leakage
- unresolved inconsistencies require substantive citation of every target without complete context or repair

### `investigation-selection.test.ts`

Common historical selection: `contribution-answers`, `contribution-results`, `m3-agentic-cutover`, `application-journey`, `application-exact-compatibility`, `immutable-capture`; caller bindings are now captured by application coordination. Old tree/displaced-subtree layout and primary replacement are retired. Attempt-only diagnostic identity is replaced under the accepted attempt/answer decision.

- request variants retain semantic outcomes without attempt reporting, pages, usage or allocation
- retained snapshots reconstruct without session enumeration after corrections, associations and inconsistencies accumulate
- unpaged content retains all accounts, displaced descendants and their corrections, full sources and exposure pairs
- revision snapshots preserve transitive causes, whole-evaluation exemptions, branches and all inconsistency reporters
- selection identity normalizes only known references and ignores irrelevant acceptance-rank shifts
- retention has no revision, proximal-citation, association-page or prose bounds
- associated selections retain the shown module or mixed organization basis and explicit subject population
- selection validation rejects wrong kinds, sessions and incomplete graphs atomically, preserving original records
- binding port cannot allocate outside its typed population or partially bind invalid batches
- interpretation support display follows retained-selection meaning instead of the Lens spelling
- arrangement is self-contained, preserves bounded disclosure and distinguishes presentation from Projection identity
- association continuation identity uses precise selected matches in both View formulas
- exact investigram inspection retains its contextual heading and explicit title overrides
- exact retained presentation keeps combined pages and frozen correction/association state across later history
- answer bindings are separate, append-only and local even for copied colliding aliases
- an empty composite remains empty after later associations and refuses their tokens
- retained off-page support can claim a new subject prefix without changing old bindings

### `investigation-revisions.test.ts`

`contribution-exposure`, `contribution-results`, `contribution-answers`, `application-exact-compatibility`: exact uses, distinct causes and delivery routes, bounded presentation with unbounded retained history, immutable prior snapshots. Recency-selected primary, whole-evaluation exemptions and automatic tree context are retired.

- primary selection searches all branches; later descendants win without erasing conflict or earlier snapshots
- per-cause propagation stops at whole-evaluation exemptions and retains independent and alternate paths
- dense citation graphs and many causes remain bounded without enumerating paths; all pages are accessible
- context pages preserve exact originals and distinguish reference availability, incomplete exposure and full correction context
- incoming inconsistencies preserve qualification and count as reporter exposure only when actually delivered
- automatic context summarizes all incoming inconsistencies honestly and follows the primary branch

### Ported and replaced mixed-file cases

- `investigator-references`: literal preservation, nested native reference traversal and independent/closed handle namespaces remain. Nested tree submission and legacy association context cases are replaced by `contribution-hosted`'s typed common codec and `contribution-exposure`/`application-exact-compatibility` acquisition and continuation checks.
- `lens-extensions`: the old objective/method/initial-tree-context fingerprint case is replaced by `contribution-dialog`'s complete operation and follow-up catalog fingerprint test and exact originating-subject tests. Every supported caller extension test remains.
- `evidence-access`: dialog cases use common invocation, production and acceptance directly. The old summary-only citation/provenance test is retired: metadata summaries do not prove full-record delivery in the common model. The response-bound guard still rejects citations to undelivered records, and known full-record evidence plus separate actual common exposure are asserted.
- `work-attribution`: cancellation of an asynchronous native source query runs inside the common dialog. Its assertion finds the source query explicitly because the common dialog first records baseline identification acquisition. Late query results remain unable to rewrite the sealed report.
- `exports-lens`: exact partial/unavailable support is resolved through `application/retained.ts`; it cannot enrich itself from a fuller answer in the same store. Missing-support refusal is exercised through the production executor in `application-exact-compatibility` (direct exact exports and partial/empty CLI cases), not a separate client compatibility helper. Round 1 removed the orphaned helper assertion; compatibility/precondition checks now use the application consumption functions used by the executor.
- `application-lifecycle`: the removed presentation binding port is no longer a fixture dependency. The real operation check capability still expires, close refuses delivery, and client failure leaves completed application work intact.
- Hosted API-key and ChatGPT transport suites use common `DialogInput`, response envelopes and submission functions; transport, usage, credentials and streaming assertions remain. Wire schema semantics are checked in `contribution-hosted` rather than obsolete nested-tree schemas.

## Identity change

`program-records@25` records removal of the obsolete native record union and store index. The retired `investigation`, `investigationEvaluation` and `investigationProjection` methods no longer enter captured Session methods. This intentional change updates captured provenance; all 18 measured journey answer keys still match the accepted caller baseline. It does not change native provider algorithms or guarantees. `method-provenance` verifies that application methods participate in identity, independently of presentation methods. The representative comparison records both revisions' exact keys and counts, alongside the changed provenance payloads.

## Limits

These tests establish structural, lifetime, delivery and interpretation-reporting behavior, not truth of generated explanations. M2 recorded trials remain the only live usability evidence. Final integrated review and human sufficiency judgment remain required. Temporary canonicalization/allocation optimization, persistence, automatic reassessment/clearance, broader UI and additional language or Lens families are outside this implementation.
