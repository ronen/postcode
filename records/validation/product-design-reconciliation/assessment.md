## Rubric and case-by-case assessment

The assessment checks (1) intelligible claim and limits without source-language literacy, (2) useful attributed labels/assertions rather than signatures serving as explanations, (3) supported computational meaning with material qualifications preserved, and (4) intelligible unmet needs distinguished from analysis failure. Rows below follow the account order in each result. Each row assesses prose, referent description and qualifications together; associations and their qualifications were also read. Identifiers such as `lookup`, `readRemote(key)` and `./adapter` act as labels: the surrounding prose explains their roles. Compact key/value notation does not replace a contract explanation.

## Exposure assessment and remaining boundaries

Explicit detail fields are not the sole attribution surface. Newly retained diagnostic paths in normal Views and non-View resolution JSON/text are now classified as attribution when rendered. Organization paths, module/compiler names and requested module names remain useful attribution/labels, not source excerpts. Project-opening and parser failures retain the existing pre-Session no-batch behavior; escaped paths and identifiers in those errors are diagnostic attribution, not source excerpts. Normal request JSON can also repeat a caller-supplied name or rejected value; these are request data, not acquired source. Analysis-context records in the observation batch may contain configuration/repository paths even when they are not human output; merely retaining those records is not an exposure event. Source acquisition and captured evidence are distinct from presentation.

The implementation classifies explicit fields it owns. It is not a general detector of code in arbitrary prose, user feedback or provider diagnostics. Feedback acknowledgments do not echo the explanation or redisplay embedded artifacts as human output. Existing credential-safe diagnostics remain bounded reports. Broader captured-basis attribution, navigation lineage, account selection, accumulated-understanding UX, persistence, structured accounts and agent protocols remain outside this task.

Historical two-build comparison scripts retain the old flags where they explicitly target historical builds; current Session measurement scripts use the new control. Historical observations retain their original version/meaning. New batches use format 4.
