## Maintenance and maturity assessment

- **Graphlib:** the scoped package has a recent release and a long history. Upstream explicitly directs users to the maintained DagreJS-scoped package. This is an established choice, but published SCC recursion is a fitness limitation here, independent of its maturity.
- **Graphology/components:** established graph ecosystem; the upstream README identifies Sigma as a consumer. Core published in 2025, while the components package last published in 2022. Mature algorithm code may legitimately release infrequently; this audit did not establish maintainer response times or infer abandonment from age. Prefer an explicit compatibility/maintenance check before adoption.
- **Commander:** long-lived, exceptionally broad ecosystem use, current ESM release and no direct runtime dependencies. Its [release notes](https://github.com/tj/commander.js/releases/tag/v15.0.0) document Node >=22.12 and the preceding major receiving security updates for 12 months. Strong maintenance posture for the shortlist.
- **string-width / wrap-ansi:** long-lived terminal utilities with very broad ecosystem use and recent publications. Unicode handling is precisely the generic responsibility worth delegating if terminal-column layout is adopted. Recent release activity does not prove terminal fidelity on every font/locale.
- **shell-quote:** long publishing history and recent release under the current maintainer, with substantial adoption. Its broader shell grammar, not package maturity, rules it out for the small literal tokenizer.
- **Zod:** established validation ecosystem, current releases and very broad adoption; dependency-free in the inspected dependencies map. The lack of savings from relational checks is the blocker, not ecosystem maturity.
- **simple-git / Execa:** long-lived and widely used, both with recent releases. Their broader process APIs entail additional dependencies and default/error translation. The latest simple-git publication is only a day old at audit time; it is evidence of activity, not of that exact release being field-proven.
- **ignore / fast-glob:** long-established and very widely used. ignore has recent publication; fast-glob has a longer release gap since January 2025. Neither gap nor popularity determines whether their traversal/policy semantics fit captured repository evidence.
- **ts-morph:** substantial adoption, multi-year publishing history and a 2026 release. Its compiler abstraction still needs explicit alignment with PostCode's pinned analyzer and host; package currency alone does not establish that.
- **Chokidar:** long-established watcher ecosystem with a 2025 major release and very broad use. Watch events remain a different input model from replayed captured probes.
- **Piscina:** multi-year worker-pool project with recent publication and substantial adoption. It is credible pooling infrastructure, but this application currently has one stateful worker.
- **Pino:** long-lived, broadly used structured logging project with current major-line publication. Extra serialization and transport machinery does not remove the current observation contract.
- **Tinybench:** multi-year benchmark project with recent publication and broad npm use. Suitable to consider for new microbenchmarks, not an equivalent replacement for the fresh-process experiment protocol.
- **fast-json-stable-stringify:** established and heavily downloaded, but no new published release since December 2019. Treat it as stable, slow-release code with uncertain current response posture, not as actively releasing software. Its serialization behavior also differs from the current canonicalizer.

These assessments combine release evidence, upstream documentation and observed adoption. They are not security audits, bus-factor studies, vulnerability-clearance claims or guarantees of future support. No package was installed to produce the audit.

## Primary API and behavior references

- [Node util.parseArgs](https://nodejs.org/api/util.html#utilparseargsconfig): built-in option parsing and token metadata; no third-party dependency needed.
- [Commander documentation](https://github.com/tj/commander.js): command/option declarations and output/exit overrides.
- [Graphology SCC API](https://graphology.github.io/standard-library/components.html): SCCs for directed/mixed graphs.
- [Graphlib project](https://github.com/dagrejs/graphlib): graph data structures, algorithm library and maintained package name.
- [Published algorithm/serializer checks](source-checks.md): exact-version archive paths and findings.
- [string-width options](https://github.com/sindresorhus/string-width#api) and [wrap-ansi options](https://github.com/chalk/wrap-ansi#api): display width, ambiguous-width choice, hard wrapping and trimming.
- [shell-quote parsing](https://github.com/ljharb/shell-quote): interpolation, operators and comments.
- [Zod schemas/refinements](https://zod.dev/api): shape validation and custom checks.
- [simple-git raw commands/configuration](https://github.com/steveukx/git-js) and [Execa](https://github.com/sindresorhus/execa): Git/process integration.
- [fast-glob options](https://github.com/mrmlnc/fast-glob) and [ignore](https://github.com/kaelzhang/node-ignore): filesystem traversal versus ignore-rule filtering.
- [ts-morph](https://github.com/dsherret/ts-morph): compiler wrapper.
- [Chokidar](https://github.com/paulmillr/chokidar): watcher behavior and options.
- [Piscina cancellation](https://github.com/piscinajs/piscina): worker termination on active-task abortion.
- [Pino](https://github.com/pinojs/pino) and [Tinybench](https://github.com/tinylibs/tinybench): logger and benchmark-library scope.

## Reproduction

`collect-evidence.py` fetches public registry metadata and npm download counts, saving only selected factual fields. Re-running it updates the snapshot to the then-current versions and week. `inspect-package-source.py` reads the versions in that snapshot and prints selected source text from public archives without installing or executing it. Neither script is production tooling or a new project dependency.
